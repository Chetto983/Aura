## How it was measured

`web/e2e/craft-live.spec.ts` (`AURA_E2E_CRAFT=1`) signs in, opens a conversation, attaches the file
through the cockpit's own presign, PUT to Garage and finalize, and posts one turn to `/agent/run`
with the attachment. It requires a `<server>__` call and a `send_file` in the turn, downloads the
asset `send_file` created from Garage, and screenshots the conversation in the cockpit.
`spikes/craft-mcp/e2e_check.py` then checks each output in `aura-sandbox:craft-spike` (the box
image from before the change, with LibreOffice, poppler and the Python Office libraries), so no
Craft server reads back its own work, and renders each result with its own editor in the box under
the recipe's fence: the view the agent itself gets.

The real files are those of `spikes/craft-mcp/README.md` (`D:/tmp/craft-real`, SHA256SUMS there).

## What the live run found

Each is a commit with the test that failed first.

1. **An attachment could not be opened right after its upload** (`89a30ca77`). The turn began before
   the processing gave the spreadsheet a document id; the agent passed its asset id to
   `document_open`, whose description still offered "a catalog uuid", and the index answered not
   found. The agent then found the spike's old copy of the file in the workspace and edited that.
   `document_open` now opens the caller's own accepted upload by its asset id, and the attachment
   block names that id for every attachment.
2. **A Craft recipe mount did not get the Craft policy** (`298542fa2`). `managedBridgePolicy` kept a
   recipe source only when `trustedRecipeActions` knew it, so every Craft tool fell back to its
   server's hints: the gateway paused turns to approve `wordcraft open_document` and
   `deckcraft add_slide`, and the 21 desktop-only tools were bridged. The Task 1–2 tests had set the
   policy by hand; the new one builds it from the catalog.
3. **The agent loop ran every multi-call batch concurrently** (`e5c643b3a`). The model emitted open,
   mark, apply and save of a redaction in one message, the save ran first, and the intact PDF went
   out as redacted; a deck's `add_slide` ran before its open. A batch that writes or calls an MCP
   server now runs in the order the model wrote it.
4. **An attached photo went to the model whole** (`936442545`): the 12.7 MB photo held the first
   model call past its 120 s deadline and the turn ended with no answer. The projection now sends
   the copy `DownscaleForVision` makes, and a photo over its pixel bound as text that says to open
   the file.
5. **GridCraft counted rows** (`ae55712a8`, `48708ec62`). `read_range` answers rows without numbers;
   the agent wrote B40 (the equity risk premium) for B39 three times out of four. The skill now
   finds a label's row with `=MATCH("*word*", 'Sheet'!A1:A300, 0)` (measured: row 39, and `INDEX`
   the 0.045 beside it).
6. **WordCraft filled the first matching blank** (`ba5954844`): a bare `n. ......` matched an
   attachment number 40 paragraphs before the determina. The skill now selects a blank with the
   words before it.
7. **DeckCraft's `add_slide` inserts after the current slide** (`ba5954844`): the closing slide landed
   second. The skill now goes to the last slide first.

Before (2) the agent asked for approvals; before (3) and (5) it reported success on files it had
not changed or had changed wrongly. Those reports came from the agent; only the checks outside
the servers caught them.

## The fence

The six servers run in the box as `landrun --best-effort --rox / --rw /workspace --rw /dev
--unrestricted-network --unrestricted-scoped --env HOME --env PATH -- <app>-cli mcp …` (the box's
`/proc`, after the stack was recreated). Through their own save tools GridCraft and FilmCraft
wrote to `/tmp` and `/root` without it, and get "Permission denied" with it, while the six spike
tasks give the same calls and outputs fenced and unfenced (`spikes/craft-mcp/FINDINGS.md` 13). The
box image contract checks the fence on every build. Garage is out of the servers' reach: the box
holds no store credentials, and only `send_file` wrote the six results there.

## What this does not show

- **One model.** Every turn ran on `gemma4:31b-cloud`. Another primary may read the skills
  differently; the GridCraft skill took two corrections before three runs in a row were right.
- **One file per server, one run each** (GridCraft three). A pass rate across many files is not
  measured; the spike's broader task set (`spikes/craft-mcp/FINDINGS.md`) was driven without the
  model.
- **The fence on another kernel.** Landlock was measured at ABI 7 on the WSL2 kernel 6.18. On a
  kernel without Landlock, `--best-effort` runs the servers unfenced; the image contract only
  proves the fence where it runs.
- **Photos over the decode bound are not seen by the model** in the turn: it reads that the image
  is too large and looks through PhotoCraft's render. A 12 MP phone photo is within the bound; this
  18.7 MP one was not.
- **The cockpit no longer edits video or photos by hand.** The removed Video Studio and photo editor
  are replaced by the agent, not by another UI; FilmCraft and PhotoCraft in the cockpit are later
  projects.
